## Abstract

Autonomous multi-agent workflows require verifiable identity, bounded delegation and revocation of derived authority. We strengthen ChainGuard-AI by replacing name-based root trust with registry-bound signed requests and durable replay protection, and by resolving permissions through authenticated parent-specific grant paths. Revocation invalidates dependent paths while preserving independent authority. A locally tested Solidity extension exposes root-attested grant ancestry and temporal validity without modifying existing public evidence. Three controlled experiments compare Merkle-batched local-EVM anchoring with cryptographic hash-chain logging, original and corrected delegation behavior, and legitimate/adversarial authorization requests. Across 24 audit runs, both blockchain commitments and externally protected hash-chain checkpoints detected the tested storage transformations; a rewriteable local hash-chain head did not. The original delegation engine incorrectly retained 60 downstream permissions after intermediate revocation, while the corrected engine retained none in the tested cases and preserved 40 independent paths. The corrected security matrix allowed 30 legitimate operations, blocked 140 attack attempts and referred ten synthetic scope-creep cases for review. These finite controlled results demonstrate the tested properties, not universal attack prevention. Blockchain contributes an external audit commitment with additional latency, storage, gas and operational assumptions; it is not the only tamper-evidence mechanism.

## Methodology

The trusted registry binds readable agent identifiers to Ethereum public addresses. Callers sign canonical application messages using EIP-191; signatures bind the operation, payload digest, domain, nonce and bounded authentication interval. The server resolves identity from trusted registry configuration and atomically consumes nonces across workers. Retained grant signatures bind holder, permission, expiry and a specific parent grant ID. Current permission is the existence of a valid authenticated path; live governance additionally requires action-time validity, current status and required blockchain evidence. A decommissioned intermediate invalidates only derived authority, while independently valid paths survive. Local policy snapshots use process locks and atomic replacement with fault-aware rollback/reload. The optional GrantAuthority contract checks root-attested ancestry and inclusive issuance/revocation, exclusive expiry, scopes and cycles. Its deployment is restricted to isolated local Hardhat in this evaluation.

Ordinary governance outcomes are represented as canonical AuditRecords, hashed with Keccak-256 and grouped into deterministic Merkle batches. The auditor compares the complete ordered inventory against externally obtained batch roots/counts. The comparison hash chain uses identical records and cryptographic hashing, with separately protected versus attacker-rewriteable checkpoints. This distinguishes commitment placement from hash-function security. The pre-existing Isolation Forest remains a behavioral review signal rather than a replacement for authorization.

## Experimental setup

Audit workloads were 10, 100, 500 and 1,000 records, three paired trials each, batch size ten, alternating variant order. Both variants used the same signed current-authorization engine and event generator. Caller signing/setup were excluded from event timers; durable replay/persistence and synchronous local receipts were included. The benchmark did not time the full governance pipeline or public-network confirmation. A protected hash-chain checkpoint and a local head replaceable by the storage attacker were tested separately against modification, deletion, insertion, reordering and full history rewriting. Timing summaries report observed trial ranges, not inferred confidence intervals.

Delegation experiments used four agent-chain depths, two versions and 20 trials per cell, plus 40 independent-path preservation cases. Original code was loaded from a pinned Git commit into isolated reference fixtures. Trace probes deliberately distinguish original flat lookups from corrected warm signed-ancestry checks. The 180-request security matrix comprised 30 legitimate operations, 140 attack attempts and ten separately classified anomalies; the operations call production components, with independent genuine HTTP/WebSocket/local-EVM tests establishing boundary usability. All new blockchain writes were local. Existing Sepolia evidence was verified read-only.

## Results

Use the exact tables in `RESULTS_AND_DISCUSSION.md` and their raw CSVs. The audit comparison contains 9,660 timed operations. The protected-checkpoint hash chain and externally anchored Merkle inventory detected all supplied tamper transformations, with no untampered false positives in the 24 complete-audit checks. Recomputing a local hash chain and replacing its only head defeated local self-consistency verification. Thus the measured integrity advantage is conditional on an external checkpoint remaining outside the storage attacker's control.

The preserved original retained 60 tested downstream permissions after intermediate revocation; corrected enforcement retained zero and preserved all 40 independent paths. The security confusion matrix was TP=140, FN=0, FP=0, TN=30, defining attack as positive and excluding REVIEW cases. Its precision/recall/F1 were 1.000 in this deliberately constructed matrix; this is not a measured real-world anomaly accuracy. Unauthorized root issuance changed from ten allowed original attempts to zero allowed corrected impersonation attempts.

## Discussion

Blockchain is justified when auditors require a separately addressable commitment and cannot trust the mutable local checkpoint. An equally protected external hash-chain checkpoint provides the same tested detection property. Synchronous anchoring, extra batch bookkeeping and RPC verification incur measurable costs; local snapshot-copying and nonce durability are part of the observed implementation overhead. No claim is made that these timings isolate consensus cost, beat optimized logging systems or predict Sepolia/mainnet latency. Signed ancestry and durable state perform more work than the original unsigned flat lookup, so revocation timing comparisons must acknowledge that assurance difference.

Preserving saved Sepolia outcomes and proofs establishes compatibility of historical evidence, not retroactive enforcement of the corrected policy. The new extension is locally tested and root-attested; agent signatures are verified off-chain, and no public grant migration was performed. Trusted clocks, enrollment, keys, enforcement storage and chain/RPC selection remain assumptions. The tests do not protect against a malicious authorized root or guarantee semantic truth/data availability.

## Conclusion

The evaluation supports the tested improvements in root authentication, replay rejection and grant-specific downstream revocation, while qualifying blockchain's value as an external witness rather than exclusive tamper detection. The source, scripts, raw trial data, source/output hashes, figures and verification artifacts make the controlled claims inspectable. These results are bounded by synthetic workloads, four-agent topologies, local automining and finite adversarial cases.

## Future work

Future evaluation should use independent real-agent datasets, larger heterogeneous delegation graphs, cold/warm and multi-host benchmarks, optimized append-only/database baselines and monitored external checkpoints. Operational work includes standardized identity interoperability, key rotation/HSMs, anti-rollback enforcement state, separately audited public extension deployment, provider/reorganization fault campaigns and explicit policy migration. Uncertain transaction reconciliation must remain fail-closed; no exactly-once public delivery guarantee is claimed.
