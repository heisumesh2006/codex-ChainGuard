# Module 5: chain-reconstructable full-agent revocation

The detailed Module 5 registry is a **separate Hardhat deployment** in `module5/data/deployment.json`. Its Module 2-compatible action, credential, and proof files are under `module5/data/`. The original `module2/deployment.json` and `module2/ethereum_state.json` remain intact for historical verification; new detailed revocations use the Module 5 deployment. To create a bundle from scratch when these Module 5 files do not exist, run `module2/.venv/Scripts/python.exe -m module5.migrate`. The migration refuses to overwrite an existing bundle. Run the demo with `module2/.venv/Scripts/python.exe -m module5.main` and tests with `module2/.venv/Scripts/python.exe -m unittest module5.tests.test_revocation -v`.

`AgentTrustRegistry.anchorRevocationDetailed()` stores the original Module 1 timezone-aware ISO-8601 `decommissioned_at` string, `ROOT_AUTHORIZER`, readable revoked permission strings, content hash, record ID, and block confirmation time. `getRevocationDetails()` exposes these values directly from contract storage. The original microsecond timestamp is `revoked_at`; `confirmed_at` and `anchored_at` identify blockchain confirmation time. The root-only transaction anchors the content hash and emits `RevocationAnchored` as before. This small PoC favors readable public evidence over gas efficiency.

`get_revocation_status(agent_id)` uses only the Module 5 deployment address/RPC, compiled ABI, and Ethereum calls/logs. A fresh process can recover Agent_C's status, original timestamp, revoker, permission names, and proof without Module 1 objects, Module 2 source JSON, or the anchor index. For an active agent, status is a current contract-state observation at `checked_block_number`; an unknown agent is reported separately. `verify_revocation_proof()` compares the supplied metadata with contract storage, commitment, receipt, event, and block. When full source JSON is supplied, it additionally calls Module 2 `verify_proof()` to validate the complete decommission action content.

Only full-agent revocation is supported. `permissions_to_revoke` may be `None`, `"ALL"`, or the complete effective-permission set. A subset raises `PARTIAL_REVOCATION_NOT_SUPPORTED`. Selective permission revocation is future work. Local decommission without a confirmed anchor raises `REVOCATION_ANCHORING_FAILED` and remains retryable through Module 2's failed record. An anchored record whose proof cannot be verified raises `REVOCATION_PROOF_FAILED` with `blockchain_anchored=True` and `revocation_complete=False`.

The audit boundary is strict: `action_timestamp > revoked_at` is post-revocation activity. Equality and the `AGENT_DECOMMISSIONED` event itself are excluded. Both timestamps must be timezone-aware ISO-8601. Action `result` is deliberately ignored by the forensic audit. The audit now needs no off-chain source record because the exact timestamp is on Ethereum.
